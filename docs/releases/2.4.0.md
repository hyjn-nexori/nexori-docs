# Nexori 2.4.0

Nexori 2.4.0 upgrades the public minigame integration surface with lifecycle callbacks, a standalone developer API artifact, and runtime spectator support for rules mods.

## Highlights

- Public minigame lifecycle callbacks.
- Real spectator runtime support for minigame spectators.
- Standalone `nexori-api` artifact for developers.
- Capture The Zone integration example and optional dependency pattern.

## Public API And Minigame Integrations

The public minigame API now includes `registerMatchLifecycleListener(...)` and `NexoriMatchLifecycleListener`.

Adapters can subscribe for one `rulesEngineId` and receive match lifecycle callbacks:

- `onMatchCreated(...)`
- `onPlayerArrived(...)`
- `onPlayerPlacementConfirmed(...)`
- `onMatchPlacementCompleted(...)`
- `onMatchCompleted(...)`
- `onMatchRuntimeClosed(...)`

Use these callbacks from an adapter or integration layer. Nexori owns orchestration, travel, placement, result submission, return-to-lobby, and runtime cleanup. Your minigame owns local session state, rules, score, win/loss detection, spectators, HUD, and private gameplay events.

The recommended optional integration shape is:

```text
Nexori callbacks -> minigame adapter -> local minigame session
private minigame event -> minigame adapter -> Nexori commands
```

The result flow uses:

- `setPlayerOutcome(...)`
- `setPlayerSpectator(...)` when needed
- `submitFinalMatchResult(...)`
- `returnPlayerToLobby(...)` when appropriate
- `closeMatchAdmission(...)` when a backend-driven match should stop accepting backfill/admission

## Spectator Runtime

`setPlayerSpectator(...)` now updates more than logical match state when the player is online.

When a player enters runtime spectator state, Nexori:

- hides the spectator from active players in the same match;
- keeps spectators visible to other spectators;
- switches the spectator to Adventure mode and enables flight;
- marks the spectator intangible and invulnerable;
- disables character collision, trigger block checks, damage block checks, and damage blocking for the spectator;
- blocks spectator interaction packets, window open/close packets, item movement packets, and item drop packets;
- filters runtime spectators out of the player spatial data used by item pickup, then restores the spatial data after pickup processing;
- can apply an optional temporary spectator model id when the integration passes one.

Nexori restores tracked spectator runtime state on cleanup, return-to-lobby, disconnect, or when the player is no longer marked as a spectator.

## Capture The Zone Example

Capture The Zone is the full source example for the optional adapter pattern:

[https://github.com/hyjn-nexori/nexori-capture-the-zone-minigame](https://github.com/hyjn-nexori/nexori-capture-the-zone-minigame)

It demonstrates:

- a gameplay core that does not call Nexori directly for match results;
- private minigame events for gameplay state changes;
- `CaptureTheZoneNexoriIntegration` as the translator between Nexori and the minigame;
- Nexori lifecycle callbacks feeding local Capture The Zone sessions;
- Capture The Zone match-finished events reporting outcomes, final result, and player return through Nexori;
- loading with Nexori installed;
- starting without Nexori installed;
- a small local session mode that can run without Nexori.

Capture The Zone also demonstrates how a minigame can publish a private spectator event and let the Nexori integration translate it to `setPlayerSpectator(...)`.

## Developer Setup

Developers compile against `nexori-api` v2.4.0 through JitPack:

```groovy
repositories {
    mavenCentral()
    maven { url = uri("https://jitpack.io") }
}

dependencies {
    compileOnly("com.github.hyjn-nexori:nexori-api:v2.4.0")
}
```

Server owners install the full `nexori-plugin.jar` from CurseForge. Do not install `nexori-api.jar` as a server mod. Do not use `implementation`. Do not shade or bundle `nexori-api` inside a minigame jar. The installed Nexori plugin provides the API classes at runtime.

## Internal
