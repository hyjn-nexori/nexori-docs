# Nexori 2.3.0

Nexori 2.3.0 expands the backend-driven flow into a full multi-lobby matchmaking and backfill model with catalog sync, admission reporting, real backfill, and explicit admission close support for rules mods.

This release matters most for:

- server owners running more than one lobby/source server
- backend developers implementing `/nexori/sync`, `/nexori/results`, and `/nexori/matches/state`
- minigame/rules mod developers integrating with backend-driven admission and late join behavior

## Highlights

### Multi-Lobby Backend-Driven Matchmaking

Backend-driven matchmaking is no longer shaped around one designated lobby server.

Multiple source/lobby servers can now contribute players to the same backend-driven queue flow while Nexori preserves one shared match identity and returns each player to the correct origin server.

This means your backend can treat several lobbies as one queue population instead of splitting them into separate local islands.

[Read backend-driven matchmaking](/concepts/backend-driven-matchmaking)

### Catalog Sync For Games And Queues

Nexori can now sync one saved game or one saved queue from one trusted server to another through the Minigames UI.

This is designed for multi-lobby backend-driven setups where queue and game definitions must stay aligned across entry servers without turning the system into a full config mirror.

[Read backend options](/features/backend-options)

### Backend Match Admission State Reporting

Nexori now reports backend-driven match admission visibility to `POST /nexori/matches/state`.

This gives your backend a clear view of whether a running match is still visible for admission decisions, how many slots are already admitted, and whether admission is still open under the policy that launched the match.

[Read the match admission state endpoint docs](/backend/match-admission-state-endpoint)

### Real Backend-Driven Backfill

Backend-driven matches can now accept real backfill.

Instead of always creating a new match, your backend can now choose an already running match with open capacity and send late joiners into that existing arena through a `BACKFILL` assignment.

This keeps the initial launch flow intact while adding a separate admission flow for late joiners.

Backfill policy is queue-driven:

- `NONE`
- `PLACEMENT_ONLY`
- `ACTIVE_WINDOW`

[Read the sync endpoint docs](/backend/sync-endpoint)

### Backend Configuration In Game

The backend config UI now exposes admission state reporting settings in addition to sync and result reporting.

Operators can now configure:

- admission state reporting enable/disable
- debounce interval
- max coalesce window
- retry interval
- stale-after window

[Read backend configuration](/backend/configuration)

### Public API: Explicit Admission Close

Rules mods can now explicitly close backend match admission for one active backend-driven match through the public Minigame API.

This is useful when a game mode reaches a phase where late joins should no longer be accepted even if the original backfill window has not expired yet.

[Read public API methods](/public-api/methods)

## What Changed For Backend Developers

Nexori now exposes three backend contracts:

- `/nexori/sync`
  Use this for backend-driven matchmaking heartbeat, queue snapshots, assignments, assignment ACKs, and `BACKFILL` launches.
- `/nexori/results`
  Use this for final match result reporting.
- `/nexori/matches/state`
  Use this for backend-driven match admission visibility, slot accounting, reservation consumption confirmation, and admission closure state.

If you are implementing the backend side, start here:

- [Backend configuration](/backend/configuration)

## What Changed For Minigame Mod Developers

The public Minigame API now covers one more important control point for backend-driven matches.

Rules mods can now:

- detect the active match
- verify ownership
- wait for placement completion
- set player outcomes during the match
- mark logical spectators
- explicitly close backend admission when the game should stop accepting late joiners
- return players separately
- submit the final result once the match is complete

If you are building a rules mod, start here:

## Compatibility Notes

- Existing local queue flows still remain available without a backend.
- Existing `LOCAL_FIFO` queues still do not coordinate across servers.
- Existing 2.2.0 integrations using `submitFinalMatchResult(...)`, `setPlayerOutcome(...)`, `returnPlayerToLobby(...)`, and the match lookup methods remain compatible.
- New integrations should use `setPlayerOutcome(...)`, `submitFinalMatchResult(...)`, and `returnPlayerToLobby(...)`.
- The backend sync contract is no longer just for launching new matches. To support real backfill, backends should handle `assignmentType=BACKFILL` and implement the match admission state endpoint.
